# V4 升级计划

目标：从"小团队内部工具"升级为结构规范、可持续维护、业务功能完整的售后管理系统。

## 已确定的决策

| 项目 | 决定 |
|---|---|
| 范围 | 工程地基与数据安全、界面升级、工单派单 + 滤芯分级、收款明细 + 统计报表 |
| 前端 | Vue 3 重写（TypeScript + Vite + Element Plus + Pinia + Vue Router） |
| 环境 | 新建独立的测试环境；正式环境继续使用 `water-storage-d0ggf2m9faaadb034` |
| 时间 | 一律北京时间（`Asia/Shanghai`） |
| 上线方式 | 新旧并行：新版在测试环境完成并验证数据迁移后，再切换正式环境；旧版保留可回退 |

## 阶段与交付物

### 阶段 0：工程地基
- 新前端放在 `web/` 目录，旧版保留在根目录直到切换
- TypeScript、ESLint、Prettier；单元测试（Vitest）与端到端测试（Playwright）
- GitHub Actions：每次提交自动检查、测试、构建，不通过不能合并
- 配置按环境区分（测试 / 正式），部署脚本一条命令完成
- 迁移原有的纯逻辑代码（日期解析、导入列识别、到期计算）并补齐测试

### 阶段 1：数据结构升级（关系型）
把"一个客户一整块 JSON"拆成多张表，便于统计、并发和审计：

| 表 | 内容 |
|---|---|
| `customers` | 客户：名称、省份、区域、长期合作、负责人 |
| `devices` | 装机记录：地址、联系人、电话、装机时间、型号、数量、安装位置、验水 |
| `filter_stages` | 滤芯分级：每台设备的每一级滤芯（如 PP 棉 / 活性炭 / RO 膜）各自的周期和上次更换日期 |
| `replacements` | 换芯记录（可关联到某一级滤芯） |
| `follow_ups` | 跟踪记录 |
| `work_orders` | 工单：类型（换芯 / 维修 / 验水 / 安装 / 催款）、状态、指派人、预约日期、完成情况 |
| `receivables` / `payments` | 应收款与每次收款 |
| `audit_log` | 操作日志：谁在什么时间改了什么（触发器自动记录） |

- 所有表：`created_at` / `updated_at` / `deleted_at`（软删除 → 回收站）、`version`（并发修改冲突检测）
- RLS：普通成员看自己负责的数据 + 指派给自己的工单涉及的客户；管理员看全部
- 迁移脚本：从现有 `customers.data` 自动转换，转换前后逐条核对数量与内容
- 每日自动备份（定时云函数导出），并演练一次恢复

### 阶段 2：界面
- 侧边导航：工作台、客户、装机记录、工单、收款、报表、成员、设置
- 列表支持表格 / 卡片两种视图，服务端分页、排序、筛选
- 手机端适合上门使用（工单列表、一键拨号、完成工单时登记换芯）
- PWA：可添加到手机桌面
- 保留并迁移现有能力：导入导出（与《格式样板》19 列兼容）、批量操作、提醒、AI 小助手

### 阶段 3：业务功能
- **滤芯分级**：按型号预设各级滤芯及周期，可逐台调整；到期按"最早到期的一级"提醒
- **工单派单**：从到期提醒一键生成工单 → 指派同事 → 待上门 / 已完成；完成时自动登记换芯
- **收款明细**：应收金额、每次收款、未收余额；催款提醒基于实际欠款
- **统计报表**：本月换芯量、收入、超期率、各区域 / 各同事工作量，可导出

## 风险与对策

| 风险 | 对策 |
|---|---|
| 数据迁移出错 | 先在测试环境迁移正式数据的副本，逐条核对；正式迁移前完整备份；旧数据表保留不删 |
| 重写期间同事无法使用 | 新旧并行，旧版一直可用，验证通过后再切换 |
| 范围过大 | 每个阶段单独交付、单独验收 |
